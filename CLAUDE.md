# Omniboard — инструкции для Claude Code

## Продукт

Omniboard — аппаратно-программный комплекс для ведения НРИ за живым столом: трекер инициативы, эффекты, веб-интерфейс (React + Vite) и бэкенд (FastAPI), данные в JSON под `data/`. Это не VTT: без виртуальных карт и цифровых кубиков как замены живого стола.

## Документация (порядок чтения)

1. `**README.md**` — точка входа: философия, стек, установка, обзор возможностей.
2. `**Omniboard_TZ.md**` — основное техническое задание (нумерованные разделы). При расхождении кода и ТЗ явно отмечать несоответствие.
3. `**Architecture_Decisions_and_Icebox.md**` — архитектурные решения (ADR), зафиксированные компромиссы и отложенные идеи (icebox). Отвечает на «почему так», дополняет ТЗ.
4. `**Progress_and_Backlog.md**` — выполненные фазы, бэклог; полезно для контекста (в т.ч. сеть и ESP32), не как единственный норматив.
5. `**Refactoring_Plan.md**` — плановые переделки.
6. `**readme_beta.md**` — бета-ограничения.
7. `**Red_Knight_Vision.md**` — долгосрочное видение; не смешивать с обязательными требованиями текущего релиза.

Игровые заметки в `data/assets/systems/.../notes/` — пользовательский контент, не спека продукта.

## Структура репозитория

- **Корень**: `README.md`, ТЗ и планы (см. выше), `package.json`, `vite.config.ts`, `requirements.txt`.
- `**src/`**: React 19 + TypeScript, UI (GM Console, Initiative Tracker и др.), i18next, WebSocket-клиент.
- `**backend/`**: Python 3.11+, FastAPI (`main.py`), роутеры (`routers/`), сервисы, движки инициативы (`engines/`), Pydantic-модели (`models.py` и связанные).
- `**scripts/**`: запуск dev (бэкенд + освобождение портов).
- `**data/**`: файловое хранилище — ассеты систем (`data/assets/`, override поверх `default/`), локали (`data/locales/`), энкаунтеры, автосейв (`state_autosave.json`), логи боя, рендер-выход (`data/render/`). Не удалять пользовательские данные без явного запроса.

## Запуск и порты (dev)

- Из корня: `npm install`, затем `**npm run dev**` — параллельно бэкенд и фронт (`concurrently`).
- **Фронт (Vite):** порт `**3000`**, `host 0.0.0.0` — UI: `http://localhost:3000` или `http://<IP>:3000` в LAN.
- **Бэкенд (Uvicorn):** в типичном dev — порт `**80`** на `0.0.0.0` (см. `scripts/start-backend.cjs`). В `vite.config.ts` прокси `/api`, `/ws`, `/assets`, `/render`, `/locales` указывают на `http://127.0.0.1` (порт 80 по умолчанию). Браузер в dev обращается к **3000**; API идёт через прокси на **80**.

Ручной бэкенд (как в подсказках локалей): `uvicorn backend.main:app --reload --host 0.0.0.0 --port 80`.

## ESP32 и дисплей миниатюры

- Экран на миниатюре: **172×320** пикселей (прямоугольный). От этого размера завязаны **портреты, композитор и экспорт PNG** для устройства; не менять холст произвольно без согласования с рендером и прошивкой.
- Интеграция на бэкенде: в первую очередь `backend/routers/hardware.py`, `backend/services/esp_manager.py`, `backend/led_resolver.py`, рендер — `backend/routers/render.py`, `backend/compositor.py`. При изменении JSON/WebSocket-контрактов учитывать потребителей (в т.ч. ESP32).

## Правила работы с кодом

- Менять только то, что нужно для задачи; без рефакторинга «заодно».
- Соблюдать стиль существующих файлов (именование, импорты, уровень комментариев).
- Домен боя: `CombatSession`, движки инициативы — согласовать с моделями бэкенда и типами фронта (`src/types.ts` и связанные модули).
- Локализация: ключи в `data/locales/<lang>/core.json` и существующие соглашения проекта.
