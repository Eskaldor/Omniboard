# Omniboard — справочник по функциям (beta)

> Рабочая версия: май 2026. Дополняйте по мере изменения UI.

Черновик для мастера и разработчика: что умеет приложение и как этим пользоваться в текущей сборке. Не заменяет [Omniboard_TZ.md](Omniboard_TZ.md), [Architecture_Decisions_and_Icebox.md](Architecture_Decisions_and_Icebox.md) и [Progress_and_Backlog.md](Progress_and_Backlog.md).

## 1. Запуск

- **Рекомендуемый режим разработки:** из корня репозитория  
`npm run dev`  
Поднимаются **фронтенд** (Vite) и **бэкенд** (Uvicorn) параллельно (`concurrently`).
- **Порты по умолчанию:**
  - фронтенд: **3000** (см. `package.json`, скрипт `dev:frontend`);
  - бэкенд: скрипт `dev:backend` запускает Uvicorn на **порту 80** (см. `scripts/start-backend.cjs`). На Windows для прослушивания порта 80 могут понадобиться права администратора; при конфликте порта смотрите `scripts/kill-port-8000.cjs` / `predev`.
- **Прокси:** запросы с фронта к `/api`, `/ws`, `/assets`, `/render`, `/locales` уходят на бэкенд (см. `vite.config.ts`).

Открывайте UI в браузере по адресу, который выводит Vite (обычно `http://localhost:3000`).

## 3. Жизненный цикл боя

1. **Добавьте акторов** (кнопка добавления, ростер, энкаунтер или вручную).
2. **Выставите инициативу** (колонка Init и т.д.) при необходимости.
3. **Начать бой** — кнопка в нижней панели. Строится очередь по выбранному **движку инициативы** (см. раздел 6).
4. В бою: **следующий ход** / **следующий раунд** (подпись меняется для Manual, Popcorn, Phase), **стоп боя** — завершение сценария (архивация логов на стороне сервера при настроенном потоке).
5. **Очистить стол** — отдельный диалог: можно сохранить закреплённых акторов (pinned) и ограничить эффекты у оставшихся (логика на бэкенде).

**Undo / Redo** — отмена и повтор шагов с ограниченной глубиной стека (см. ADR-3 в архитектурном файле).

## 4. Таблица инициативы

- **Клик по строке** — в зависимости от режима движка и Manual Mode: передача хода, выбор актора и т.д. (см. ADR-14 в документации по архитектуре).
- **Двойной клик** по ячейке текстовой колонки — открытие редактора длинного текста (Text Editor).
- **Колонки чисел** — часто с **StatValue** (база, формулы, оверрайды): часть полей только для чтения или вычисляется по `mechanics.json` / колонкам.
- **Быстрый бросок** — у колонок с флагом «rollable» появляется кнопка броска (кубик).
- **Группы чекбоксов (`checkbox_group`)** — экономика действий: бейджи или точки, автосброс по политике на начало хода на бэкенде.
- **Эффекты** — кнопка «+» у актора, снятие по клику; длительность тикает при смене раунда по правилам движка.
- **Закрепление актора (pinned)** — защита от полной очистки стола.
- **Портрет / миниатюра в строке** — превью рендера для привязанной Omnimini, если настроено.

Колонка **Roll Matrix** в таблице показывается, если на сервере уже есть предброски (`prerolls`); полноценный столбец матрицы в UI может быть ограничен (см. комментарии в `App.tsx`).

## 5. Конфигуратор (шестерёнка)

Модальное окно с боковыми разделами (см. `ConfigModal` и вкладки):


| Раздел                    | Содержание                                                                             |
| ------------------------- | -------------------------------------------------------------------------------------- |
| **Система**               | Активная TTRPG-система, пресеты, экспорт/импорт конфигурации колонок                   |
| **Отображение (Display)** | Центрирование таблицы, цвета групп/фракций, закрепление первой/последней колонки, язык |
| **Колонки**               | Типы полей, группы, ширина, механика (readonly, roll, формулы), режим Simple/Expert    |
| **Язык**                  | Выбор языка интерфейса из доступных в `data/locales/`                                  |


Сохранение колонок пишет `columns.json` системы и раскладывает переводы имён в `data/systems/<система>/locales/`.

## 6. Движки инициативы и ручной режим

В настройках боя (PATCH через UI) задаётся `**engine_type`**:

- **standard** — классическая очередь по убыванию инициативы, simultaneous-группы как один слот.
- **popcorn** — передача хода по клику, смена раунда через «следующий раунд» / логику движка.
- **phase** — фазы: клики только в «верхней» активной фазе.

**Manual Mode (ручной режим)** — смягчает жёсткую очередь; мастер может передать ход выбором строки. Переключатель в интерфейсе рядом с действиями боя (`ManualModeToggle` / тулбар).

Если в `data/systems/<система>/` лежит файл `**logic.py`**, смена движка через API может блокироваться (задел под кастомную логику; загрузка движка из файла — в разработке, см. `backend/engines/manager.py`).

## 8. Легенда, группы, цвета

- Панель **легенды** в шапке: цвета ролей (игрок, враг, союзник, нейтрал), переключатели отображения групповых/фракционных цветов в таблице.
- **Группы акторов** — режим выделения нескольких строк, создание группы (sequential / simultaneous), опционально общий профиль экрана для отряда (`GroupCreateModal`).

## 9. Omnimini: миниатюры и железо


| Модалка                   | Назначение                                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Miniatures**            | Раскладка полей на экране 172×320, профили, предпросмотр рендера, привязка к актору.                                                                               |
| **Hardware (устройства)** | Список Omnimini, online/offline, яркость экрана (сессия), режим привязки **к актору** или **к слоту очереди** (линия инициативы), push, тест LED/экрана, Discover. |
| **LED-профили**           | Пресеты подсветки по системе (`led_profiles.json`, merge с default).                                                                                               |
| **Триггеры железа**       | Правила событий (`led_triggers.json`), в том числе **initiative_shift** для анимации смены картинки при слотовой привязке.                                         |


Связь с физическими устройствами — **HTTP** к прошивке и **mDNS**, не отдельный WebSocket для минек (см. ADR-15).

## 10. Консоль мастера (GM Console)

Нижняя выдвижная панель: режимы **Note**, **Roll**, **AI**.

- **Заметки** — карточки, файлы заметок в папках системы (см. компоненты в `src/components/GMConsole/`).
- **Броски (Roll)** — строка терминала с языком токенов (полная грамматика, таблица и контракт попапа — **[Omniboard_TZ.md §2.6](Omniboard_TZ.md)**; архитектура — **ADR-24** в [Architecture_Decisions_and_Icebox.md](Architecture_Decisions_and_Icebox.md)):
  - **`@Имя`** — к какому актёру относится бросок; можно несколько имён — запросы уйдут по очереди с **своим** резолвом статов и макросов.
  - **`!ключ`** — подстановка значения стата (longest-match; для «красивых» подписей в отдельном сегменте — `!{текст ключа}`). Один только `!стат` в сегменте разворачивается в шаблон броска колонки из конфига.
  - **`$макрос`** — формула из мини-чарника (система + кастом актёра, override).
  - **`;`** — несколько независимых бросков подряд (отдельные записи в логе).
  - **`#текст`** — комментарий к броску.
  - Попап автодополнения при вводе `@` / `!` / `$` (для `!`/`$` сначала укажите хотя бы одного актёра через `@`, иначе покажется подсказка); в режимах `!`/`$` доступны вставка **суммой** (`+`) или **серией** (`;`).
  - Справка в UI (плейсхолдер / `?` / тултип) синхронизирована с §2.6; запросы уходят на `/api/combat/roll` и `/api/combat/actors/{id}/roll` уже с **развёрнутыми** формулами.
- **AI** — задел под помощника (зависит от конфигурации и ключей).

Переключение режимов иконками; **Tab** на пустой строке может циклически менять режим (в т.ч. войти в Roll с пустого инпута).

## 11. Лог боя и файлы на диске

- Лог может писаться в `data/logs/latest_combat.json` и `.md` (фоновый поток на бэкенде).
- GM-заметка в лог — отдельный API (см. ТЗ §4).
- Открытие папки логов с машины сервера — `POST /api/logs/open_folder` (если используете).

## 12. Где лежат данные (для ручного редактирования)


| Путь                             | Содержание                                                                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `data/systems/<система>/`        | `columns.json`, `effects.json`, опционально overrides для layouts, bars, LED, mechanics, matrix, `led_triggers.json`, `locales/*.json` |
| `data/assets/default/config/`    | Базовые JSON, общие для всех систем                                                                                                    |
| `data/assets/systems/<система>/` | Картинки и файлы ассетов override                                                                                                      |
| `data/actors/<система>/`         | Ростер                                                                                                                                 |
| `data/encounters/`               | Сохранённые энкаунтеры по системам                                                                                                     |
| `data/locales/<язык>/core.json`  | Ядро UI                                                                                                                                |
| `data/miniatures.json`           | Глобальный реестр Omnimini                                                                                                             |
| `data/state_autosave.json`       | Автосейв сессии боя                                                                                                                    |


Дублирующие или старые файлы локалей в `data/locales/` (например, `system_*.json`) могут сосуществовать с путями внутри системы — ориентируйтесь на актуальную загрузку через API `/api/locales/...` и структуру в ТЗ.

## 14. Ограничения и «бета»

- Справочник составлен по коду и документам; отдельные кнопки могут меняться между коммитами.
- Не описаны все edge cases математики кубов и все комбинации движков — при сомнениях смотрите `backend/engines/` и ТЗ.
- Отдельная страница `/gm-console` в виде полноэкранной ширмы — в беклоге; сейчас основной UX — встроенная нижняя консоль.

При обновлении функционала имеет смысл дополнять этот файл короткими пунктами «как пользоваться» и датой в шапке.
